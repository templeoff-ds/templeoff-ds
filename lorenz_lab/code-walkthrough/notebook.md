# Построчный разбор lorenz.ipynb

[Сам Notebook](../lorenz.ipynb) · [Маршрут чтения](../code-walkthrough.md)

В Notebook нумерация относится к физическим строкам исходного текста конкретной **кодовой** ячейки, а не к строкам JSON-файла. Markdown-ячейки содержат пояснения и ссылки на сохранённые изображения и не выполняют Python. Код использует те же функции, что main.py; отдельного скрытого интегратора в Notebook нет.

## Порядок и состояние ядра

Запускайте Restart Kernel → Run All сверху вниз. Переменные config, output, p, data живут между ячейками; запуск только нижней ячейки в свежем ядре может дать NameError. Если поменяли конфигурацию, нужно повторить чтение, расчёт, графики, GIF и отчёт. Старые сохранённые outputs не доказывают, что ячейка выполнена после изменения входа.

## Кодовая ячейка 2: позиция 5, id `lorenz-03`

| Строка внутри ячейки | Python | Пояснение |
| --- | --- | --- |
| 1 | <code>from lorenz import Parameters, rhs, jacobian, equilibria</code> | Импорт: параметры, правая часть, Якобиан и аналитические равновесия. Имена становятся доступны далее в этом модуле. |
| 2 | <code>import numpy as np</code> | Импорт: векторные массивы, нормы и линейная алгебра (сокращение np). Имена становятся доступны далее в этом модуле. |
| 3 | <code>p = Parameters(config[&#x27;sigma&#x27;], config[&#x27;rho&#x27;], config[&#x27;beta&#x27;])</code> | Создаёт Parameters по полям config, а не использует молча параметры по умолчанию. |
| 4 | <code>print(&#x27;f(u0) =&#x27;, rhs(0, config[&#x27;initial_state&#x27;], p))</code> | Печатает начальную скорость из исходного состояния. Это не одношаговый результат и не стартовая координата. |
| 5 | <code>for name, u in equilibria(p).items():</code> | Перебирает аналитические равновесия этой модели. |
| 6 | <code>    print(name, u, &#x27;спектр:&#x27;, np.linalg.eigvals(jacobian(u,p)))</code> | Для каждой точки печатает координаты и спектр её Якобиана. Расчёт новой траектории здесь ещё не запускается. |

## Кодовая ячейка 7: позиция 15, id `lorenz-13`

| Строка внутри ячейки | Python | Пояснение |
| --- | --- | --- |
| 1 | <code>import subprocess, sys</code> | Импорт: запуск проверки в отдельном процессе; путь к текущему Python-интерпретатору sys.executable. Имена становятся доступны далее в этом модуле. |
| 2 | <code>completed = subprocess.run([sys.executable, &#x27;-m&#x27;, &#x27;unittest&#x27;, &#x27;discover&#x27;, &#x27;-s&#x27;, &#x27;tests&#x27;, &#x27;-v&#x27;], capture_output=True, text=True)</code> | Запускает отдельный процесс текущего Python: unittest discover по tests. capture_output сохраняет stdout/stderr в объекте completed, text=True декодирует их в строки. |
| 3 | <code>print(completed.stdout + completed.stderr)</code> | Печатает оба потока, включая подробный отчёт тестов. Порядок слияния stdout+stderr не обязан воспроизводить точное перемежение потоков во времени. |
| 4 | <code>completed.check_returncode()</code> | Возбуждает исключение при ненулевом коде завершения тестов. Одного печатания текста с failed было бы недостаточно для автоматического отказа ячейки. |
