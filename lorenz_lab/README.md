# Лабораторная работа: система Лоренца

**Построчное объяснение программы:** [маршрут чтения, формы массивов и реальные стадии RK4](code-walkthrough.md).

**Математика с нуля:** [справочник понятий](math-glossary.md) — определения, формулы и примеры непосредственно из этой работы.

Готовое численное исследование: самостоятельные Эйлер/RK4, библиотечный RK45, контроль эталона, сходимость, чувствительность и локальная устойчивость. Включены результаты вычислений, семь PNG, GIF, Notebook, подробный отчёт и 32 вопроса для защиты. Работа начинается без примера одногруппника по указанию пользователя; сравнение с ним ещё не выполнено.

## Быстрый запуск

Нужен Python 3.11+ и доступ к пакетам из requirements.txt. На Linux/macOS:

```bash
cd lorenz_lab
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python main.py
```

Windows PowerShell: создать окружение `py -m venv .venv`, активировать `.venv\Scripts\Activate.ps1` или вызывать `.venv\Scripts\python.exe` напрямую. Для Notebook дополнительно установите JupyterLab: `python -m pip install jupyterlab`; затем `python -m jupyter lab lorenz.ipynb` и выполните **Restart Kernel → Run All**. В ноутбуке должны использоваться пакеты из того же окружения. JupyterLab — дополнительный интерфейс, а не обязательная зависимость консольного расчёта.

`python main.py` создаёт/обновляет численные данные, рисунки, GIF и отчёт. Время зависит от машины; анимация — самый тяжёлый этап. Графический интерфейс и интернет при вычислении не нужны. Backend Matplotlib — Agg, GIF сохраняется PillowWriter без ffmpeg.

```bash
python main.py --skip-animation
python main.py --config config.json --output results_alternative
```

Первый вариант не пересоздаёт GIF и не обещает его актуальность после изменения конфигурации: при изменении параметров для окончательных результатов нужен полный запуск. Второй сохраняет отдельный комплект с собственным report.md. Главный report.md обновляется только при выводе в стандартный results/. Пути по умолчанию разрешаются от каталога проекта, поэтому `python /полный/путь/lorenz_lab/main.py` тоже работает.

## Конфигурация и трактовка чисел

Параметры находятся в config.json. Основной режим: σ=10, ρ=28, β=8/3, u₀=(1,1,1), δ₀=(10⁻⁸,0,0), t∈[0,40], h=0,01. Длины основного и короткого интервалов должны делиться на выбранные фиксированные шаги. Для сохранения представленного эксперимента окно наклона должно находиться внутри интервала, perturbation должно быть ненулевым, а short_end и transient_end нужно согласовывать с t_start/t_end.

В основной серии Эйлера h=0,04 возникает переполнение. Это сохранённый исследовательский результат `nonfinite`, а не сбой всего проекта. Все основные траектории с h=0,01 конечны. Для проверки первого порядка отдельно добавлены меньшие шаги; исходная серия не заменена.

`metrics.csv` содержит максимум и конечную ошибку на полном интервале, короткую ошибку, медиану времени интегрирования, принятые шаги, nfev и число выходных точек. Длительное расхождение с численным эталоном не ранжирует точность методов в хаотическом режиме. Наклон ln расстояния не является точным максимальным показателем Ляпунова. Подробнее — report.md.

Файл trajectories.npz читается через `numpy.load`; ключи — t, reference, euler, rk4, rk45, perturbed, distance, fine_t, fine_distance. Никакой pickled-объект внутри не нужен. summary.json сохраняет конфигурацию, версии и метрики последнего расчёта. Времена работы зависят от платформы; поздние фазы хаотических траекторий также чувствительны к последним разрядам арифметики.

## Подготовка к защите

1. Прочитать отчёт от понятия производной до результатов, самостоятельно выписать один шаг Эйлера.
2. Понять, почему у RK4 четыре стадии, а не выучить только последнюю формулу.
3. Уметь воспроизвести нахождение O,C± и все девять элементов Якобиана.
4. Повторить объяснение переполнения грубого Эйлера, асимптотического порядка и ограничений численного эталона.
5. Пройти plan-zashchity.md и показать тесты, данные и GIF.

Проверка ячеек Notebook и команда чистого прогона описаны в validation.json. Программа не содержит утверждения о сохранении энергии или формального доказательства хаоса. Сверка с присланным ранее примером остаётся отдельным этапом.


## Если преподаватель спрашивает «почему именно это число?»

Начните с [constants-explained.md](constants-explained.md): назначения и обоснования всех настроек, коэффициентов RK4, порогов проверок и оформления. [constants-results.md](constants-results.md) содержит реальные сравнения, [constants-index.md](constants-index.md) — построчный индекс чисел в Python-коде.

```bash
python parameter_study.py
python build_constant_index.py
```

Первую команду следует запускать после основного исследования, на исходном классическом config.json: диапазоны альтернатив в constants-study.json согласованы с ним. Это отдельный эксперимент, `python main.py` его автоматически не повторяет. Вторая команда обновляет документацию и номера строк по текущему коду. Малые/большие альтернативы сохраняются в results/constants_study/; основная конфигурация и базовые результаты не заменяются.

Важно: эти проверки не доказывают глобальную оптимальность настроек. Некоторые числа заданы моделью или формулой и не должны экспериментально «оптимизироваться». После изменения модели нужно пересмотреть диапазоны и интерпретацию. В тестах теперь явно установлено `rtol=0` для алгебраических абсолютных проверок.
